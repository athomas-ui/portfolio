From Leading People to Securing Technology.

After years of running programs, teaching STEM, and keeping operations on track, Andrew Thomas is bringing that same accountability to cybersecurity and governance, risk, and compliance.

By Andrew ThomasCybersecurity & GRC AnalystChicago, IL

I built my career where people, technology, and accountability meet. As a STEM instructor, I taught cybersecurity, drone coding, robotics, and AI. Earlier roles in AV support and logistics sharpened my troubleshooting and operational discipline.

Today I am CompTIA Security+ certified, finishing an Associate of Science in Computer Science with a cybersecurity concentration, and interning with i.c.stars Cycle 60, where I am turning training into impact through hands-on coding and confidential client consulting.

Project Spotlight In progress · playable prototype

Cyber//Breach

A basic cybersecurity training game that helps people understand the fundamentals of internet security by making decisions, not just reading about them.

Objective
Teach security basics such as spotting a phishing email through short missions where the right call earns XP and a higher rank.
My role
Creator and developer: game design, front-end code, testing, and documentation.
What works today
  • Character selection, then a player card that tracks rank, XP, and missions completed out of five.
  • Mission 01, “The Bait,” a phishing scenario with four possible responses.
  • An answer-checking engine that compares the player's choice to an answer key, shows feedback on the page, and adds 50 XP per correct answer.
  • Answer locking after the first click, so XP cannot be farmed by re-clicking.
What I learned
Verifying logic with hand-checked math instead of assumptions, and using clear variable names so nested loops stay readable.

Built with

  • HTML
  • CSS
  • JavaScript
  • Git & GitHub
  • GitHub Pages

Evidence

Play the prototype (opens in a new tab) View the code (opens in a new tab)
Open the build log

Week 1

  1. Built a real answer-checking engine that compares the chosen answer against an answer key instead of just logging picks.
  2. Wired live feedback onto the mission screen, with separate messages for correct and incorrect answers.
  3. Connected XP to the decision engine: read the number from the page, converted it to real math, and added 50 points per correct answer.
  4. Proved the engine with hand-checked math, confirming the final XP matched exactly what four correct clicks should produce.

Week 2

  1. Locked each question after one answer so XP can't be farmed by re-clicking.
  2. Proved the lock works on both outcomes: buttons freeze visually and functionally either way.
  3. Learned and applied variable shadowing, keeping loop names separate so nested code stays readable.

Next

The player card is already built to track five missions; the next step is building the missions after Mission 01.
